# Расписание МГУ — запуск на сервере

Минимальный production-комплект Telegram-бота. Требуется Python 3.12 или новее.

## Mini App

Приложение находится в `app/miniapp/static`: чёрные карточки на светлом фоне,
лаймовое выделение группы, цветные отметки пар, ближайшее занятие и весь день.
Выбор группы сохраняется на устройстве. Номера пар привязаны к сетке от 9:40;
при первом открытии после последней пары показывается завтра. Кнопка «Сегодня»
всегда позволяет явно открыть текущий день.

Нижняя панель переключает отдельные экраны «Расписание», «Личное» и «Профиль».
Выбор группы вынесен в отдельный экран: изменения применяются только после
«Показать расписание», возврат назад не меняет активное расписание.
При открытии белое и лаймовое кольца за 1,3 секунды перемещаются в знак ФГУ.
Заставка завершается независимо от загрузки данных и SDK; при системном
уменьшении движения пропускается.

### Личное расписание через ЦДО

На экране «Личное» используются учётные данные ЦДО факультета. Python-сервер
повторяет наблюдаемый протокол веб-клиента «МойФГУ»: POST `/api/auth/login`,
GET `/api/web/students/me`, POST `/api/web/timetable/student` на
`https://my.spa.msu.ru`. Идентификатор студента берётся из вошедшего аккаунта,
его нельзя подменить параметром запроса приложения. Ответы с занятиями
нормализуются в существующую модель, включая аудитории и подгруппы.

После входа и восстановления сессии группа выбирается автоматически: ID из
`/students/me` сопоставляется с публичным `/api/web/groups`, откуда берутся
направление и курс. Значения подставляются в выбор группы и сохраняются на
устройстве; предыдущий ручной выбор при входе заменяется группой аккаунта.
Если каталог временно недоступен или ID не найден, группа не угадывается по
названию, а личное расписание по ID студента продолжает работать.
Подгруппы не выводятся из номера группы: персональные пары запрашиваются
отдельно для студента, даже когда два пользователя учатся в одной группе.

В профиле «Моя группа · ЦДО» показывает исключительно группу аккаунта ЦДО,
а не текущий ручной выбор в общем расписании. Без входа предлагается
подключить ЦДО, при выходе это поле очищается. Вкладка «Личное» использует
только персональный запрос студента, независимо от выбранной вручную группы.
Приближение двойным тапом отключено через `touch-action: manipulation`;
прокрутка и масштабирование двумя пальцами остаются доступны.

Пароль не сохраняется в базе, localStorage или логах. Поле очищается сразу при
отправке; токен и cookies внешнего сайта остаются в отдельном HTTP-клиенте на
сервере для каждого проверенного Telegram ID. Сессия хранится только в памяти,
не дольше часа: после перезапуска сервера, истечения сессии или выхода нужен
новый вход. «Выйти из ЦДО» отключает именно подключение в Mini App; кабинет
«МойФГУ» в другом браузере продолжает работать. Вход ограничен пятью попытками
в минуту на пользователя. При ошибке источника приложение не подменяет
личные пары расписанием группы и не объявляет ошибочный ответ пустым днём.

Контракты найдены в публичном веб-клиенте, это не документированный API для
сторонних приложений. Они могут измениться. Автотесты проверяют адаптер на
контролируемых ответах, включая ошибки и изоляцию пользователей. Реальный
вход и совпадение личных занятий необходимо отдельно проверить своим
аккаунтом внутри Mini App; пароль в чат или настройки бота не передавайте.

Полноэкранный режим запрашивается автоматически через
`Telegram.WebApp.requestFullscreen()` для клиентов с API 8.0+, вместе с `expand()`.
Учитываются `safeAreaInset` и `contentSafeAreaInset`; на неподдерживаемых клиентах
приложение остаётся развёрнутым до доступной высоты. Есть отдельная кнопка fullscreen.

Сервер проверяет HMAC-подпись Telegram `initData` и срок её действия (24 часа).
Токен не передаётся в браузер, данные расписания запрашиваются у сайта МГУ сервером.
Открытие простой ссылки во внешнем браузере показывает инструкцию войти через бота.

Настройки `.env` или окружения:

```dotenv
WIDGETS_ENABLED=false
MINI_APP_ENABLED=true
MINI_APP_URL=https://ВАШ-HTTPS-АДРЕС
PORT=8080
```

`python main.py` запускает HTTP-сервер и Telegram polling в одном процессе.
Когда `MINI_APP_URL` задан, бот устанавливает кнопку меню «Расписание» и добавляет
кнопку открытия приложения в ответ `/start`. `MINI_APP_URL` должен вести на корень
этого же сервера, доступный снаружи по HTTPS. Для Bothost подключите домен и направьте
входящий трафик на порт `PORT`; TLS завершается на стороне хостинга.

### Обновление на Bothost

В репозитории есть `Dockerfile`: он запускает бота и HTTP-сервер через
`python main.py`, слушающий `0.0.0.0:8080`. В контейнер копируются только
приложение, зависимости и точка входа; локальный `.env` в образ не попадает.

1. Обновите проект из ветки `main` репозитория `churzyanka67-art/msu123`.
2. Подключите HTTPS-домен к HTTP-порту 8080 (или к значению `PORT` хостинга).
3. В переменных окружения сохраните текущий `BOT_TOKEN` бота расписания.
   Укажите `WIDGETS_ENABLED=false`, `MINI_APP_ENABLED=true`, `PORT=8080` и
   `MINI_APP_URL=https://АДРЕС-НА-BOTHOST` (без пути `/assets` или `/api`).
4. Перед запуском на хостинге остановите локальный polling для этого токена.
5. Пересоберите/перезапустите бота. В логах должны появиться запуск Mini App
   на нужном порту и `Start polling`, без `Conflict` и `401`.
6. Откройте `https://АДРЕС-НА-BOTHOST/healthz`: ожидается `ok`.
   Затем отправьте `/start` в Telegram и откройте Mini App кнопкой.

Адрес `trycloudflare.com` относится только к локальному Mac и не подходит
для постоянного `MINI_APP_URL` на Bothost.

### Локальный запуск

Остановите экземпляр на хостинге. В локальном `.env` должен быть текущий токен
от BotFather: старый отозванный токен даст `401 Unauthorized`.

Для временного HTTPS-доступа можно запустить официальный Cloudflare Quick Tunnel:

```bash
cloudflared tunnel --url http://127.0.0.1:8080 --no-autoupdate
```

Скопируйте выданный адрес `https://…trycloudflare.com` в `MINI_APP_URL` и выполните:

```bash
python main.py
```

Затем откройте бота, отправьте `/start` и нажмите «Открыть расписание».
Туннель и процесс бота должны оставаться запущенными; закрытие/сон Mac прервёт доступ.
После нового запуска Quick Tunnel адрес меняется, и `MINI_APP_URL` нужно обновить.

Только HTTP-сервер, без Telegram polling: `python -m app.miniapp`.
Предпросмотр на сохранённых данных, с отдельным фиктивным токеном и портом 8081:
`python -m tools.preview_miniapp`. Этот режим предназначен для браузерных тестов,
он не использует токен настоящего бота. Настоящий сервер не принимает запросы без
подписанного Telegram `initData`.

Браузерная проверка экранов: `node tools/check_miniapp.cjs` (нужны Playwright
и Google Chrome). Предпросмотр полностью изолирован от реального ЦДО:
его ответы задаются `httpx.MockTransport`; фиктивный пароль `valid` используется
только в локальном тестовом режиме. Тесты сохраняют снимки в `preview/`.

## HTML-виджеты

HTML-виджеты отключены по умолчанию: Telegram ограничил их доступность для обычных
ботов. При `WIDGETS_ENABLED=true` `/start` открывает HTML-виджет по референсу:
чёрная карточка, лаймовые акценты, цветные отметки пар. Направление и курс
выбираются кнопками, затем группа выделяется и подтверждается кнопкой
«Показать расписание». Дни и страницы переключаются внутри сообщения.
Вкладка «Ближайшая» показывает ближайшую незавершённую пару выбранного дня,
а нажатие на строку пары раскрывает полные сведения, включая подгруппы.

Нужен Telegram с поддержкой Bot API 10.4 widgets. В production виджеты
доступны только в личных чатах. Для обычного текстового интерфейса задайте
`WIDGETS_ENABLED=false` в окружении хостинга или `.env` и перезапустите бота.
Существующее сообщение не меняет формат: после перезапуска отправьте `/start`.

HTML не загружает внешние ресурсы; сайт МГУ по-прежнему запрашивает Python-бот.
Данные экрана разделяются между `chat_data` и `public_data`, каждое поле не больше
1024 UTF-8 байт. Личные виджеты не являются shared widgets. Длинные дни и данные
разделяются на страницы; сообщение не превышает высоту, предусмотренную Telegram.
Для новых методов API используется небольшой адаптер поверх aiogram 3.31.0;
`widget_query` явно включён в polling и обрабатывается до определения типа события.

Проверка без токена (зависимости проекта должны быть установлены):

```bash
python -m unittest discover -s tests -v
python -m tools.preview_widgets
```

Предпросмотр сохраняется в `preview/index.html`. Он использует сохранённые
реальные ответы сайта от 9 сентября, а не актуальное расписание.
Только проверка в настоящем Telegram подтверждает работу нативного рендерера:
`/start` → направление → курс → группа → показать → следующий день → назад;
проверьте также «Ближайшая», раскрытие пары и повтор после ошибки источника.

Если Telegram отвечает `INPUT_MEDIA_WIDGET_NOT_ALLOWED`, команда `/widget_test`
в личке отправляет минимальный статический виджет без CSS, JavaScript, состояния
и запросов. Команда не меняет активный экран. Если и этот запрос отклонён,
передайте полный ответ Telegram для проверки ограничений бота/чата.
Сам код ошибки не подтверждает необходимость whitelist или настройки BotFather.
Если нужен обычный рабочий интерфейс на время диагностики, установите
`WIDGETS_ENABLED=false` и перезапустите бота.

При выборе группы бот показывает сегодняшний день. Если последняя сегодняшняя пара
уже закончилась (по московскому времени), сразу открывается завтра. Учитывается
самое позднее фактическое время окончания, включая особое время и подгруппы.
Кнопками можно вернуться к сегодняшнему дню. Если сегодня занятий нет, показывается
сегодняшний пустой день; перехода через выходные к ближайшему учебному дню нет.

## Загрузка из GitHub

```bash
git clone АДРЕС_РЕПОЗИТОРИЯ
cd ИМЯ_РЕПОЗИТОРИЯ
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
cp .env.example .env
nano .env
```

В `.env` укажите токен:

```dotenv
BOT_TOKEN=токен_от_BotFather
CACHE_ENABLED=true
```

На хостингах вроде Bothost задайте эти же значения в настройках переменных окружения проекта. Файл `.env` на сервер загружать не требуется: переменная `BOT_TOKEN` имеет приоритет.

Файл `.env` исключён из Git. Не публикуйте его и не добавляйте токен в исходный код.

Проверка живого сайта МГУ без запуска Telegram:

```bash
.venv/bin/python -m app.smoke
```

Разовый запуск бота:

```bash
.venv/bin/python main.py
```

## Постоянный запуск на Ubuntu/Debian

Откройте `deploy/raspisanie-bot.service.example`, замените `YOUR_USER` и `/opt/raspisanie` на пользователя и абсолютный путь проекта. Затем:

```bash
sudo cp deploy/raspisanie-bot.service.example /etc/systemd/system/raspisanie-bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now raspisanie-bot
sudo systemctl status raspisanie-bot
```

Просмотр логов:

```bash
journalctl -u raspisanie-bot -f
```

После обновления из GitHub:

```bash
git pull
.venv/bin/python -m pip install -r requirements.txt
sudo systemctl restart raspisanie-bot
```

Запускайте только один экземпляр бота на один Telegram-токен.
