# Расписание МГУ — запуск на сервере

Минимальный production-комплект Telegram-бота. Требуется Python 3.12 или новее.

## HTML-виджеты

По умолчанию `/start` открывает интерактивный HTML-виджет по референсу:
чёрная карточка, лаймовые акценты, цветные отметки пар. Направление и курс
выбираются кнопками, затем группа выделяется и подтверждается кнопкой
«Показать расписание». Дни и страницы переключаются внутри сообщения.
Вкладка «Ближайшая» показывает ближайшую незавершённую пару выбранного дня,
а нажатие на строку пары раскрывает полные сведения, включая подгруппы.

Нужен Telegram с поддержкой Bot API 10.4 widgets. В production виджеты
доступны только в личных чатах. Для обычного текстового интерфейса задайте
`WIDGETS_ENABLED=false` в окружении хостинга или `.env` и перезапустите бота.
Существующее сообщение не меняет формат: после перезапуска отправьте `/start`.

HTML не загружает внешние ресурсы; сайт МГУ по-прежнему запрашивает Python-бот.
Данные экрана разделяются между `chat_data` и `public_data`, каждое поле не больше
1024 UTF-8 байт. Личные виджеты не являются shared widgets. Длинные дни и данные
разделяются на страницы; сообщение не превышает высоту, предусмотренную Telegram.
Для новых методов API используется небольшой адаптер поверх aiogram 3.31.0;
`widget_query` явно включён в polling и обрабатывается до определения типа события.

Проверка без токена (зависимости проекта должны быть установлены):

```bash
python -m unittest discover -s tests -v
python -m tools.preview_widgets
```

Предпросмотр сохраняется в `preview/index.html`. Он использует сохранённые
реальные ответы сайта от 9 сентября, а не актуальное расписание.
Только проверка в настоящем Telegram подтверждает работу нативного рендерера:
`/start` → направление → курс → группа → показать → следующий день → назад;
проверьте также «Ближайшая», раскрытие пары и повтор после ошибки источника.

При выборе группы бот показывает сегодняшний день. Если последняя сегодняшняя пара
уже закончилась (по московскому времени), сразу открывается завтра. Учитывается
самое позднее фактическое время окончания, включая особое время и подгруппы.
Кнопками можно вернуться к сегодняшнему дню. Если сегодня занятий нет, показывается
сегодняшний пустой день; перехода через выходные к ближайшему учебному дню нет.

## Загрузка из GitHub

```bash
git clone АДРЕС_РЕПОЗИТОРИЯ
cd ИМЯ_РЕПОЗИТОРИЯ
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
cp .env.example .env
nano .env
```

В `.env` укажите токен:

```dotenv
BOT_TOKEN=токен_от_BotFather
CACHE_ENABLED=true
```

На хостингах вроде Bothost задайте эти же значения в настройках переменных окружения проекта. Файл `.env` на сервер загружать не требуется: переменная `BOT_TOKEN` имеет приоритет.

Файл `.env` исключён из Git. Не публикуйте его и не добавляйте токен в исходный код.

Проверка живого сайта МГУ без запуска Telegram:

```bash
.venv/bin/python -m app.smoke
```

Разовый запуск бота:

```bash
.venv/bin/python main.py
```

## Постоянный запуск на Ubuntu/Debian

Откройте `deploy/raspisanie-bot.service.example`, замените `YOUR_USER` и `/opt/raspisanie` на пользователя и абсолютный путь проекта. Затем:

```bash
sudo cp deploy/raspisanie-bot.service.example /etc/systemd/system/raspisanie-bot.service
sudo systemctl daemon-reload
sudo systemctl enable --now raspisanie-bot
sudo systemctl status raspisanie-bot
```

Просмотр логов:

```bash
journalctl -u raspisanie-bot -f
```

После обновления из GitHub:

```bash
git pull
.venv/bin/python -m pip install -r requirements.txt
sudo systemctl restart raspisanie-bot
```

Запускайте только один экземпляр бота на один Telegram-токен.
